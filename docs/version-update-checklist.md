# Version update checklist

Files to touch when bumping the version (X.Y.Z). All occurrences are plain
text; search the tree for the previous version string to confirm nothing was
missed (ignore `bin/` and `obj/`, which are regenerated by the build).

| File | What to change |
| --- | --- |
| `Tfx.csproj` | `<Version>X.Y.Z</Version>` — source of the window title, status-bar version, assembly version, and the packaging scripts' output names |
| `README.md` | `Version: X.Y.Z` line near the top |
| `README.ja.md` | `Version: X.Y.Z` line near the top |
| `CHECKLIST.md` | Window-title example (`tfx X.Y.Z - <パス>`) and the「製品バージョン」line |
| `CHANGELOG.md` | Rename the `## Unreleased` section to `## X.Y.Z` (or add a new `## X.Y.Z` section at the top, in English) |

After editing:

1. `dotnet build Tfx.csproj` — confirms the csproj still parses and regenerates the assembly attributes.
2. `dotnet test Tfx.Tests` (run from PowerShell).
3. Report the changes and stop. Do not commit, tag, or push without an explicit instruction; the commit message convention is the bare version number (e.g. `0.9.17`).

Not part of a version bump: `docs/roadmap.md` (feature status only), `scripts/*.ps1` (read the version from `Tfx.csproj`).
